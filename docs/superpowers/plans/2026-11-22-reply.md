# Reply from the board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user answer a Claude session's choice list, permission prompt, or idle prompt from Meerkat's
drawer, safely, with the answer shown on the card afterwards.

**Architecture:** A pure recognizer turns a 120-line `agent.read` into a typed `Prompt` with a fingerprint.
`GET /output` returns it; `POST /reply` re-reads, re-recognizes, compares fingerprints and only then sends
through a separate `ReplySender` that can call exactly `agent.prompt`, `agent.send_keys`, `pane.send_text`.
The page carries a per-launch token in a meta tag and sends it in a custom header.

**Tech Stack:** TypeScript 6, Node 24.22.3 `node:http`, React 19 + Vite, Vitest + Testing Library,
Playwright with the fake Herdr in `test-support/fake-herdr.ts`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-22-reply-design.md` (read it first; this plan argues from it).

## Global Constraints

- No code comments; no `eslint-disable`, `@ts-ignore`, `@ts-expect-error` or rules turned off. Fix the code.
- Red/green TDD for every change: failing test, run it, minimal code, run it, commit.
- No new dependencies. `crypto` and `node:http` only on the server.
- Mac only, bind `127.0.0.1`, Host check stays (421). No CORS headers anywhere.
- Never send input to any Herdr session except the one scratch session started in Task 0. Never `herdr server
  stop`, never bare `herdr`.
- Don't touch `.github/` (another worker owns CI) or `~/ghq/github.com/hokita/meerkat` (the user's running copy).
- Keys allowed: `1`–`9`, `enter`, `esc` (plus `up`/`down` only if Task 0 proves digits don't select).
- Text: 1–4000 chars after trim, no control characters; `\n` only for `prompt` actions. Body ≤ 8 KB.
- Reply ids remembered 5 minutes per pane. `lastReply` kept 10 minutes. Summary text ≤ 80 chars.
- Prettier (`npm run format:check`), `npm run lint`, `npm run typecheck`, `npm test`, `npm run test:e2e` all
  green before each commit that touches code.

## Review Focus

1. A long Bash command whose request block starts above the 120-line window: the rule line is missing, so it
   must be `unrecognized`, never a permission with a truncated command. Test in Task 3.
2. Claude's own prose numbered list ("1. Review Tasks 6–7.") while the session is idle: never `choice`. Test in
   Task 3 (fixture `prose-list-idle.txt`).
3. The user answers in the terminal while the drawer is open, then taps in Meerkat: 409, nothing sent. Test in
   Task 7 (`refuses when the fresh fingerprint differs`) and Task 10.
4. Meerkat restarted while the page stayed open: stale token → 403 → page reloads once, not a loop. Test in
   Task 8 (`reloads once on 403`).
5. Session closes between the drawer read and the tap: 404 and nothing sent, drawer says "Session closed".
   Test in Task 7.
