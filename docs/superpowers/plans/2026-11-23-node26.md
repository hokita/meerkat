# Node 26 LTS (26.13.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every Node pin in meerkat from 24.22.3 to 26.13.1 and prove that lint, typecheck, tests, build, e2e and a real server start all pass on Node 26.13.1.

**Architecture:** meerkat has no cloud deploy. Its "production" is `npm start` in the user's main checkout on their Mac, and the Node version comes from the Volta pin in `package.json`. CI pins Node with `setup-node`, and `scripts/check-node-pins.sh` (run in CI) makes sure every pin agrees. The change edits pins and docs only, with no source changes expected. The pin checker is the red/green test.

**Tech Stack:** Node 26.13.1 (npm 11.20.0, V8 14.6, ABI 147), npm, TypeScript 6.0.3, Vite 8.3.8, Vitest 5.1.1, Playwright 1.65.1, GitHub Actions, Volta.

**Spec:** the task brief from 2026-11-23 (user decisions: meerkat runs on the Mac via Volta, and the user OK'd Volta fetching node 26.13.1 on Meerkat's next start. Don't change the Mac's Volta default or global tools.) A local cross-repo survey (not in this repo) gave the starting list. Its meerkat facts came from `60163e1`, so every fact below was re-checked on `a15f568` (#6), and the branch was then rebased onto `336d833` (#7), which changes no pin, dependency or lockfile.

## Node 24 → 26 risks for this repo

The jump crosses two semver-major releases, 25.0.0 and 26.0.0. Both release notes were read on 2026-11-23.

| Change | Where meerkat could feel it | Covered by |
|---|---|---|
| 26: `Readable` reads one buffer at a time | `src/server/reply.ts:257` `readBody` (flowing `data` events and a size limit). Chunks may arrive in different sizes | `src/server/reply.test.ts`, `http.test.ts`, e2e `reply.spec.ts` |
| 26: extensionless CJS exception removed for `"type":"module"` | `package.json:5` is `"type": "module"`. The only extensionless tracked file is `LICENSE`, and the bash script is not run by Node | build + start |
| 25: Web Storage on by default. 26: `localStorage` is `undefined` without `--localstorage-file` | Vitest `web` project (jsdom). `src/web/replyApi.ts:30` reads `window.sessionStorage`, and tests inject storage | `npm test` (web project) |
| 26: Undici 8 | server code uses no `fetch`. Web `fetch` runs in Chromium. Tests stub fetch | `npm test`, e2e |
| 26: `writeHeader`/`_stream_*` removed, `module.register` deprecated (DEP0205); 25: `SlowBuffer`, `fs.F_OK`, FileHandle GC-close EOL, `ErrorEvent` global | grep of `src`, `test-support`, `e2e`, `scripts`, configs: no use | full suite. A deep transitive use would show as a failure or warning |
| ABI 137 → 147 | no native modules except optional `fsevents` (not ABI-bound) | `npm ci` on 26 |
| 26: Temporal on by default, V8 14.6 | none | full suite |

## Review Focus

1. **Volta auto-fetch trap.** Once `package.json` pins 26.13.1, any `node`/`npm` reached through a Volta shim in this worktree makes Volta fetch 26.13.1 into `~/.volta`, which changes the Mac early. Every command after Task 1's pin edit must run with the worktree-local Node first on `PATH`. Task 2 Step 1 checks this before and after.
2. **Port and socket collision with the live Meerkat.** Keep away from `4321` and the real Herdr socket. e2e uses `43219` and a fake Herdr. The smoke start uses `MEERKAT_PORT=43220` and a socket path that doesn't exist.
3. **Lockfile drift.** npm 11.20.0 (Node 26) and npm 11.19.1 (Node 24.22.3) must not rewrite `package-lock.json`. `git diff --exit-code package-lock.json` after `npm ci`.
4. **A pin missed by the checker.** The checker counts exactly 5 `node-version:` lines and 1 `"node":` line. A repo-wide grep for `24\.22\.3` outside the historical docs must return nothing.
5. **Deprecation warnings at runtime.** A transitive DEP0205 (`module.register`) or DEP0201 hit only shows as a warning. The smoke start captures stderr, and it must contain no `DeprecationWarning`.

## Deploy and post-merge verification

Merging deploys nothing automatically. `ci.yml` runs only on `pull_request`. `audit-nightly.yml` runs on `schedule` (18:20 UTC) and `workflow_dispatch`. There is no push or deploy workflow. "Production" is the Meerkat running from the user's main checkout. These steps are for the user (or for me, once they say so), and none of them changes the Volta default:

1. In the main checkout: stop the running Meerkat, then `git pull`.
2. `npm ci`. Volta uses node 26.13.1 (already fetched during verification, see Execution notes; otherwise it fetches it here). `node_modules` was built under 24, so a clean install is the safe way. npm 11.20 prints an `install-scripts … fsevents@2.3.3` warning: expected and harmless (fsevents has no install script and ships a prebuilt binary).
3. `npm start`. Check:
   - the log prints `Meerkat on http://localhost:4321`
   - `node -v` in that directory prints `v26.13.1`
   - `lsof -a -p "$(lsof -nP -tiTCP:4321 -sTCP:LISTEN)" -d txt` shows `~/.volta/tools/image/node/26.13.1/bin/node`
   - the board loads at http://localhost:4321 with live sessions
   - opening a drawer shows output
4. `volta list node` still shows the same default runtime as before, and global tools are unchanged.
5. Optional: the next scheduled `Audit (nightly)` run (or a manual dispatch, run by the user) passes, and both audit jobs log Node `v26.13.1`.

Rollback: revert the PR on main, `git pull`, `npm ci`, restart. Volta goes back to 24.22.3, which is still installed.
